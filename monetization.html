Soloco 怎么赚钱

商业化与 GTM 叙事 (Monetization & Go-to-Market)
Soloco · Earthborn Lab · 2026

01 The Frame

先把最容易被质疑的那句话主动说出来，反而能让整套论述站稳：

ToC 不是收入，ToC 是漏斗、护城河和研发实验室。
真正的收入来自市场（Marketplace）和 ToB。我们照这个事实来排兵布阵——不指望那个讨人喜欢的免费产品来养活公司。

承认这一点不是认输，而是把资源投在对的地方。免费的 ToC 产品要被当作获客和生态种子来衡量，而不是按 ARPU 考核。

02 The Position

目标用户是任何已经买了 Claude 或 Codex 订阅的人。这个看似简单的定义，重新定义了产品本身。

这意味着 Soloco 不是一个 agent 平台，而是用户已经付过钱的那份订阅之上的一层。我们不转售 token，模型成本由用户自己承担。

你已经在为一个天才付费。
Soloco 把这个天才变成一家公司。

这是一个比"卖 agent 基础设施"强得多的站位：边际模型成本几乎为零，因此我们可以激进地免费、激进地病毒式增长——这是靠转售 token 赚钱的对手在结构上学不来的。

03 The Money Map

三层结构，一套策略。

第一层 · ToC（免费／低价）：漏斗

自带订阅的 AI 组织。对我们几乎零成本（用户自带 token）。它的任务是获客 + 病毒传播 + 给市场播种。只做轻度变现：Pro 席位解锁记忆持久化、更高并发、跨模型组织、私有模板。

第二层 · 市场 / CLIPHUB：可规模化的毛利

创作者发布"组织模板"（尽调组织、内容工厂、融资材料组织……），用户 fork 或订阅，我们抽成。近乎零边际成本，网络效应增长：组织越多 → 价值越大 → 用户越多 → 创作者越多。

第三层 · ToB：真正的钱在这里

把模板化的 AI 组织部署进真实公司，卖点是我们已经建好的东西——治理、审计日志、预算硬上限、决策检查点、公司级数据隔离。高客单价，通过公司内部的 ToC 拥护者自下而上落地。

04 The Precedent

这套打法不是我们发明的。它是过去十五年最主流的软件商业模式——我们只是把它套用到一个新品类：AI 组织。

  • GitHub：对个人免费 → Marketplace（Actions / Apps 生态抽成）→ GitHub Enterprise。免费 ToC 漏斗 → 市场 → ToB，一模一样。
  • Shopify：平台 + App Store（对生态抽成）+ Shopify Plus（企业版）。
  • Atlassian：自下而上免费扩散 + Marketplace（庞大的第三方应用分成）+ 企业版。
  • Figma：免费、病毒式协作 → Community（模板／插件）→ Organization / Enterprise。
  • Docker / GitLab / MongoDB / HashiCorp：开源或免费扩散 → 面向组织的治理与安全层收费。
  • Unity / Unreal：免费引擎 → 资产商店抽成 + 企业 / runtime 收费。

在这些公司里，免费的那一层从来不是收入。收入是对生态的抽成，加上面向组织的治理层。
Soloco 之于 AI 组织，正如 GitHub 之于代码。

05 The Loop

让这三层成为一套策略而非三门生意的，是它们互相喂养：

免费 ToC 用户成为拥护者 → 他发布／fork 的模板暴露出哪类组织有真实需求 → 这些被验证的模板加上我们的治理能力，被卖回他所在的公司，成为 ToB 产品。

免费用户就是 ToB 成交的 SDR。CLIPHUB 就是研发实验室。被 fork 一万次的模板，本身就是被需求验证过的 ToB 产品。

06 No Vertical Guessing

这一点回应一个常见顾虑："不想做垂直，外面有数据更强的人能把垂直做得更好。"

你永远不必猜垂直，市场会告诉你。我们在平台层保持水平，让需求把垂直经验性地浮现出来——而不是去赌一个垂直、再硬扛数据更强的在位者。

哪个组织模板被 fork 一万次，那个就是被验证过的 ToB 产品。

07 The Business Case

  • 市场规模：每一个 Claude / Codex 订阅用户都是一次预付费的免费试用。纯自下而上的 PLG，我们不背 token 成本。
  • 防御性：护城河不是模型（正在快速商品化），而是组织可读性 + 复利记忆 + 市场网络效应。它能扛过下一个模型的发布。
  • 可扩展性：市场抽成几乎零边际成本；ToB 客单价高。ToC 成本能压低，正因为用户自带 token。
  • 一句话定位："我们不是一个 AI 应用，我们是 AI 组织的平台和市场——agent 经济的 Shopify / GitHub 层。"

08 Feasibility

  • 最贵的部分已经建好了。审计、预算硬上限、治理、检查点、公司级隔离——control-plane 不变量已经在仓库里。ToB 比看起来近得多，是加固，不是从零开始。
  • 范围已经被收窄。按新论点，旧 roadmap 的 S4（webhook 信号闭环 + 22 个 adapter）移出核心，省下约四分之一的工作量。
  • 市场是薄层，不是第二个引擎。CLIPHUB = 模板版本化 + 发布／fork + 发现，叠在主线本就会产出的模板之上。它很小。
  • 要诚实标注的风险：自带订阅的并发上限、对 Claude Code 与 Codex CLI 的平台／ToS 依赖、以及记忆持久化是我们唯一真正承担的基础设施成本（token 不是，存储与检索是——这正是用 Pro 来收费的点）。

09 Objections

对每个会被反复问到的问题，提前给答案。

"ToC 免费，是不是在为一个未必出现的市场烧钱？"

下行风险是有界的：ToC 基础设施便宜（自带 token），市场近乎零边际成本，唯一的真实开销（记忆）被 Pro 挡住。我们不像对手那样补贴 token。

"Anthropic / OpenAI 为什么不会自己做？"

他们围绕单一模型垂直整合。一个跨模型、厂商中立的组织层加一个中立市场，既不符合他们的利益，也不在他们的路线图上。我们是瑞士。

"市场是不是另一个完整产品，会拖垮主线？"

不会。市场是后置阶段且很薄。涌现式 ToC 主循环在做到无可辩驳之前，是唯一焦点。

"ToB 的多租户和安全是不是太重？"

那是后期阶段，而且最难的部分（隔离、审计、治理）已经存在。是集成 adapter + 租户加固，不是重写。

10 Concurrency as Upsell

把自带订阅的并发约束，变成不靠转售 token 的增值阶梯：

  • 暴露一个"组织产能"仪表。单订阅 = 一个不大的组织，仪表诚实地显示出来。
  • 让产能成为高级用户愿意买上去的东西：接上 Claude Max、再接 Codex、再加席位 → 一个肉眼可见更大、更快、跨模型的公司。"全都买，跑一家更大的公司。"
  • 这给了一条原生于自带订阅、不需要 token 毛利的变现轴：产能／并发 + 跨模型解锁 = Pro。

而且对并发的诚实本身就是信任——这和"可读的组织"整套论点完全契合。

11 The Bet

我们在赌什么，以及需要什么样的共识与支持：

  • ToC 是漏斗、不是收入——用漏斗／市场播种／ToB 线索来考核它，而不是 ARPU。
  • 优先投涌现式主循环 + 记忆——这是产品的第一性焦点。
  • 把 CLIPHUB 定为薄范围的下一步——发布／fork／版本化 + 发现。
  • 点名 1–2 个 ToB 共建客户——一个跨境贸易场景的合作伙伴是理想的早期试点。

从转售算力，到出售组织能力。
从一个免费应用，到一个平台 + 一个市场 + 一条 ToB 收入线。
ToC 负责被爱，市场和 ToB 负责赚钱。
