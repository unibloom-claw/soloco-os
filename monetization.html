Soloco 怎么赚钱

商业化与 GTM 叙事 (Monetization & Go-to-Market)
Soloco · Earthborn Lab · 2026

01 The Frame

我们想要推出的产品 Soloco 大量的 feature 都会免费提供，即使有很多用户，但我们也不会选择收费——这是 by design 的。

免费产品是入口、是护城河、是需求实验室。
收入来自市场（Marketplace）和企业客户(Enterprise)。

我们从第一天就按这个结构分配资源：免费产品负责增长与口碑，市场和企业负责收入——各司其职。

02 The Position

目标用户是任何已经买了 Claude Code 或 Codex 订阅计划的人。这个看似简单的定义，重新定义了产品本身。

这意味着 Soloco 不是一个Token分发工具，而是用户已经付过钱的那份订阅之上的一层。我们不转售算力，模型成本由用户自己承担。

你已经在为一个天才付费。
Soloco 把这个天才变成一个AI Native的组织为你长周期地、主动式地服务。

这是一个比"卖工具"完全不同的站位：我们的边际成本几乎为零，因此可以激进地免费、激进地增长——这是与靠转售算力赚钱的对手在策略上的不同之处。

03 The Money Map

三层结构，一套策略。

第一层 · 个人版（免费／低价）：漏斗

自带订阅的 AI 组织。对我们几乎零成本（用户自带订阅、自付算力）。它的任务是获客 + 口碑传播 + 给市场播种。只做轻度变现：Pro 私有组织数据隔离服务，组织记忆数据托管服务。

第二层 · Soloco Hub（模板市场）：可规模化的毛利

创作者发布"组织模板"（尽调组织、内容工厂、融资材料组织……），用户一键复用或订阅，我们抽成。近乎零边际成本，网络效应增长：组织越多 → 价值越大 → 用户越多 → 创作者越多。

第三层 · 企业客户：真正的钱在这里

把模板化的 AI 组织部署进真实公司，卖点是我们已经建好的东西——治理、审计、预算上限、决策审批、数据隔离。客单价高，通过公司内部的免费用户自下而上组装更大的工作流，实现 ROI 最大化。

企业真正要买的不是"更多 Agent"，而是一个AI Native 组织的治理入口：管理者可以在 UI 里看见组织结构、任务流、审批点和权限边界；技术团队也可以通过 CLI 接入同一套治理面，让用户自己的 Agent 被纳入董事会席位、预算规则和审计记录之中。

04 The Precedent

这套打法不是我们发明的。它是过去十五年最主流的软件商业模式——我们只是把它套用到一个新品类：AI 组织。

  • GitHub：对个人免费 → Marketplace（应用生态抽成）→ 企业版。免费个人漏斗 → 市场 → 企业，一模一样。
  • Shopify：平台 + App Store（对生态抽成）+ Shopify Plus（企业版）。
  • Atlassian：自下而上免费扩散 + 庞大的第三方应用市场分成 + 企业版。
  • Figma：免费、口碑式协作 → 社区（模板／插件）→ 企业版。
  • Docker / GitLab / MongoDB：免费扩散 → 面向组织的治理与安全层收费。
  • Unity / Unreal：免费引擎 → 资产商店抽成 + 企业收费。

在这些公司里，免费的那一层从来不是收入。收入是对生态的抽成，加上面向组织的治理层。
Soloco 之于 AI 组织，正如 GitHub 之于代码。

05 The Loop

让这三层成为一套策略而非三门生意的，是它们互相喂养：

免费用户成为拥护者 → 他发布／复用的模板暴露出哪类组织有真实需求 → 这些被验证的模板加上我们的治理能力，被卖回他所在的公司，成为企业产品。

免费用户就是企业成交的线索来源。Soloco Hub 就是一个免费的需求研究室。被复用一万次的模板，本身就是被需求验证过的企业产品。

06 No Vertical Guessing

要不要押一个垂直？我们的答案很明确：不押。毕竟外面有数据壁垒更强的玩家。

你永远不必猜垂直，市场会替你选。我们在平台层保持水平，让需求把垂直自己浮现出来——而不是去赌一个垂直、再硬扛数据更强的在位者。

哪个组织模板被复用一万次，那个就是被验证过的企业产品。

07 The Business Case

  • 市场规模：每一个 Claude / Codex 订阅用户都是一次预付费的免费试用。纯自下而上的自然扩散，我们不背算力成本。
  • 防御性：护城河不是Agent能力（不与大厂Agent CLI竞争），而是组织的可治理性 + 组织记忆 + 市场网络效应。
  • 可扩展性：市场抽成几乎零边际成本；企业客单价高。免费产品成本能压低，正因为用户自带订阅。
  • 一句话定位："我们不是一个 AI 应用，我们是 AI 组织的平台和市场——AI 组织的 Shopify / GitHub。"

08 Feasibility

  • 最贵的部分已经建好了。把 AI 组织变得可治理、可审计、有预算上限、数据隔离——这些"让企业敢用"的底层能力，已经在产品里。企业版比看起来近得多。
  • 范围已经聚焦。我们把非核心的投入砍掉，集中优化产品主线体验。Soloco Hub 是唯一的扩展点。
  • 市场是薄层，不是第二个产品。Soloco Hub = 发布／复用／版本化 + 发现，叠在主线本就会产出的模板之上，工作量很小。
  • 订阅管理是用户价值，不是算力生意。Soloco 帮用户理解自己已经买下的 Claude / Codex 用量窗口，自动规划 5 小时额度和一周额度，把有限 Token 分配到最值得做的任务上。我们不卖更多 Token，而是让用户少浪费已经付费的 Token。
  • 唯一真实的基础设施成本是"云托管"。默认形态可以是本地组织：用户自带订阅、自付算力，我们只提供组织层、治理层和模板层。只有当用户希望这个组织长期在线、跨设备运行、保留组织记忆、定时执行任务、接入团队权限和审计记录时，才需要 Soloco 承担云端基础设施。这不是补贴算力，而是托管一家 AI Native 组织的运行环境——也正好是 Pro 和企业版最自然的收费边界。

09 Objections

几个最常被问到的问题，以及我们的回答。

"免费产品，是不是在为一个未必出现的市场烧钱？"

下行风险是有界的：免费产品成本低（用户自带算力），市场近乎零边际成本，唯一的真实开销（记忆）被 Pro 挡住。我们不像对手那样补贴算力。

"Anthropic / OpenAI 为什么不会自己做？"

他们围绕单一模型垂直整合。一个支持跨模型路由、对基座模型保持客观中立的组织层，加一个路由各家模型的模板市场，这类形态既不符合他们的利益，也不是他们的重心。

"市场是不是另一个完整产品，会拖垮主线？"

不会。它是后置的薄层。免费主循环在做到无可辩驳之前，是唯一焦点。

"企业版的多租户和安全是不是太重？"

那是后期阶段，而且最难的部分（隔离、审计、治理）已经存在。主要是把已有能力对接进客户系统、再做多租户加固，不是重写。

10 Capacity as Upsell

Capacity as Upsell 不是"帮用户买更多 Token"，而是把用户已经拥有的订阅，组织成一套可理解、可调度、可扩展的生产系统。

这个模式能成立，是因为个人 AI 订阅天然有三个结构性限制：额度是分窗口释放的，能力分散在不同模型里，任务之间会争抢上下文和等待时间。普通用户看到的是"今天额度又不够了"；Soloco 看到的是一个可以被排班、路由和升级的组织产能表。

  • 先让约束可见。单订阅就是一个小组织：有预算、有峰值、有冷却时间。Soloco 把这些边界诚实地显示出来，用户才知道当前组织能承诺什么、不能承诺什么。
  • 再把约束变成调度。同样一份额度，随机聊天会被消耗掉；放进组织里，会被拆成任务优先级、模型路由、批处理窗口、等待队列和复盘记忆。产能增长先来自浪费减少，而不是算力加购。
  • 最后让升级有明确回报。当用户真的需要更大的组织，Soloco 可以接上 Claude Max、Codex、Gemini 或更多席位，让不同模型承担不同部门和任务。升级购买的不是抽象额度，而是更大的并行度、更短的等待时间、更强的跨模型组织能力。"全都买，跑一家更大的公司。"

所以这条变现轴的顺序很重要：免费层帮助用户把已购订阅用明白，Pro 层帮助用户把多个订阅和多个模型治理起来，企业层帮助公司把这种产能接进真实权限、审批和审计系统。对产能边界的诚实本身就是信任——这和"可治理的组织"整套论点完全契合。

11 The Bet

我们在尝试构建的共识是：

  • 免费产品是漏斗、不是收入——用获客／市场播种／企业线索来考核它，而不是用它直接赚多少钱。
  • AI Native 的组织治理 + 组织记忆——这是产品的第一焦点。
  • 把 Soloco Hub 定为薄范围的下一步——发布／复用／版本化 + 发现。
  • 点名 1–2 个企业共建客户——一个跨境贸易场景的合作伙伴是理想的早期试点。

从转售算力，到出售组织能力。
从一个免费应用，到一个平台 + 一个市场 + 一条企业收入线。
免费产品负责构建生态，市场和企业负责盈利。
